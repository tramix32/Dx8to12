CAVEATS
====================================================================
* D3D8 is COM.  The only named import from d3d8.dll is
  Direct3DCreate8; every other call is indirect through a vtable,
  so it cannot appear in the PE import table.
* This resolves calls made through interface pointers held in
  GLOBAL variables, discovered transitively from Direct3DCreate8.
  IDirect3D8 and IDirect3DDevice8 are globals, so their coverage
  is essentially complete.
* Textures, surfaces and buffers created into heap structures
  (RenderWare stores them inside RwRaster) are NOT tracked, so
  IDirect3DTexture8::LockRect and friends are under-reported.
  Only the few resource pointers that happen to live in globals
  show up above.
* Call-site counts are STATIC (how many places in the code call
  the method), not runtime frequency.  RenderWare funnels render
  state through single wrapper functions, which is why e.g.
  SetRenderState has one call site but runs thousands of times
  per frame.
* Reachability is not proven: a resolved call site may sit in
  code that never executes.
